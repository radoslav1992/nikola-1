# Внедряване на управлявания каталог и ElevenLabs

Кодът включва функционалностите, но не създава автоматично платени облачни ресурси. В PR няма истински Cloudflare IDs, API ключове или телефонен номер за агента. Използвайте отделни staging ресурси преди production.

## 1. Cloudflare ресурси

В акаунта, който притежава Worker `ni-imoti`:

```bash
npm ci
npx wrangler login
npx wrangler d1 create ni-imoti
npx wrangler r2 bucket create ni-imoti-media
```

Добавете върнатия D1 ID в `wrangler.jsonc` и активирайте:

```jsonc
"d1_databases": [{
  "binding": "DB",
  "database_name": "ni-imoti",
  "database_id": "ИДЕНТИФИКАТОРЪТ-ОТ-CLOUDFLARE",
  "migrations_dir": "migrations"
}],
"r2_buckets": [{ "binding": "MEDIA", "bucket_name": "ni-imoti-media" }]
```

R2 bucket-ът трябва да остане частен, без публичен r2.dev или custom domain. `/media/…` проверява дали снимката е част от публикуван имот; администраторът вижда и черновите.

```bash
npx wrangler d1 migrations apply ni-imoti --remote
```

За локална разработка използвайте `--local`. За staging дайте отделни имена и IDs в отделен Wrangler конфигурационен файл; не тествайте импорти върху production D1. KV binding `LISTINGS` е полезен за кеша на източника/отзивите, но не замества D1.

### Повторен опит след `incomplete input`

Ако първата миграция е прекъснала при създаването на тригерите, обновете локалния код и я изпълнете отново:

```bash
git pull --ff-only
npx wrangler d1 migrations apply DB --remote
```

Тригерите използват `SELECT RAISE(...) WHERE ...`, без вложен `CASE … END`, за съвместимост с обработката на SQL през отдалечения D1 API. Миграцията използва `IF NOT EXISTS`: таблици и данни, създадени при предишен опит през Console, се запазват. Не изтривайте базата и не отбелязвайте ръчно миграцията като изпълнена.

След успех проверете в D1 Console:

```sql
SELECT name FROM sqlite_master WHERE type='trigger' ORDER BY name;
SELECT name FROM d1_migrations ORDER BY id;
```

Очакват се три тригера (`prevent_slot_overlap`, `reopen_slot`, `reserve_slot`) и запис `0001_managed_catalog.sql` в историята на миграциите.

## 2. Достъп до админ панела

`ADMIN_PASSWORD_HASH` е PBKDF2 хеш, генериран от включения скрипт. Пример за Bash, без паролата да влиза в историята на командите:

```bash
read -rs -p 'Admin password (at least 14 characters): ' NI_ADMIN_PASSWORD
printf '%s' "$NI_ADMIN_PASSWORD" | node scripts/hash-admin-password.mjs | npx wrangler secret put ADMIN_PASSWORD_HASH
unset NI_ADMIN_PASSWORD
openssl rand -hex 32 | npx wrangler secret put ADMIN_SESSION_SECRET
openssl rand -hex 32 | npx wrangler secret put AGENT_TOOL_SECRET
```

Сесията е 12 часа, HttpOnly, Secure, SameSite=Strict. Промяната на паролата или session secret обезсилва старите сесии. Входът има ограничение на опитите. Админ API изисква точен same-origin за запис. Използвайте HTTPS, включително в staging.

## 3. ElevenLabs

Запазете server-side ключ с необходимите права за agents, workspace secrets, conversations, knowledge (ако ползвате външни документи) и phone numbers:

```bash
npx wrangler secret put ELEVENLABS_API_KEY
```

Настройте `SITE_URL` на **точния публичен HTTPS домейн**. Агентът използва този адрес за инструментите и за allowlist. API ключът и тайният ключ за инструментите не се изпращат в браузъра.

За историята на разговорите:

1. Създайте HMAC webhook в ElevenLabs за `https://ВАШИЯТ-ДОМЕЙН/api/elevenlabs/webhook`.
2. Запазете подписващия secret като `ELEVENLABS_WEBHOOK_SECRET` в Worker-а. Запазете webhook ID като `ELEVENLABS_WEBHOOK_ID` (variable).
3. Настройката на агента свързва този webhook **само с агента на НИ Имоти**, за transcript и call initiation failure събития. Не сменяйте общите настройки на несвързани агенти.
4. Настройте/проверете достъпния ElevenLabs кредит и подходящ глас за български и английски. Кодът задава `eleven_flash_v2_5`, който поддържа и двата езика ([официални модели](https://elevenlabs.io/docs/overview/models)).

```bash
npx wrangler secret put ELEVENLABS_WEBHOOK_SECRET
```

След deploy отворете `/admin` → **Настройки**. Въведете Voice ID, изберете текст/глас достъп, записване и срок, запазете, после натиснете **„Създай агента в ElevenLabs“**. При следващи промени: **„Приложи настройките“**. Създава се отделен агент с таг `ni-imoti-managed`; съществуващ чужд агент не се редактира. Сървърният инструментен secret се пази в ElevenLabs Secret Store и се предава по reference.

Реалният каталог се търси чрез server tools. Допълнителни текстови документи (.txt/.md) се качват/редактират в **База знания** и се четат от агента през `read_knowledge`; не се копират променливи цени в статична AI база. За PDF/Word първо извлечете проверения текст и го добавете тук. Никола вижда всички записани запитвания, огледи, транскрипции и лични бележки в панела. Агентът записва контекста в запитването/уговорката и не може да чете лични бележки или чужди разговори.

При липсващ webhook има резервно ръчно обновяване на последните 20 приключили разговора. Cron го изпълнява също на всеки 6 часа. Webhook-ът е основният канал, който покрива всички разговори; ръчният бутон не е пълен исторически импорт.

## 4. Телефония

Основният телефон/WhatsApp/Viber е **+359 884 128 117**. За агента е нужен **отделен, подходящ номер** в ElevenLabs (например SIP/Twilio). Номер, зает от друг агент, се отказва от кода преди каквато и да е промяна.

| Режим                | Поведение                                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------------------- |
| Само сайт            | Текстов и гласов разговор в сайта; телефонът остава директен контакт                                          |
| Входящи към агента   | Избраният отделен номер приема обаждания; по изрична молба може да прехвърли към Никола                       |
| Пропуснати обаждания | Операторът пренасочва при неотговаряне/заето към номера на агента; агентът записва заявка за обратно обаждане |

В режима за пропуснати обаждания няма transfer обратно към оригиналния номер, за да няма цикъл. Условното пренасочване се настройва при оператора; сайтът не може да го включи. Ако смените режима/номера, приложете настройките. Предишен номер се освобождава само ако още е свързан с агента на този сайт.

Аудиото се пази в ElevenLabs според настройките; панелът го подава през удостоверен server proxy. В D1 се пазят транскрипция, резюме, канал и продължителност. Няма публични URL адреси за записи. Срокът важи за разговорите и webhook събитията; клиентските запитвания, уговорките и ръчните бележки са отделни работни записи. В началото винаги се съобщава за транскрипция и, ако е включено, аудиозапис. Гласът в сайта започва само след действие на посетителя.

## 5. Първи каталог

1. `/admin` → **Имоти** → **Обнови от SUPRIMMO**. Всички нови записи са чернови.
2. За избран имот заредете пълното описание и снимките. При настроен R2 снимките се копират поотделно в собственото хранилище, с показан напредък.
3. Редактирайте BG съдържанието, действителното село, района, проверените факти и източниците им. Точния адрес пазете само в личното поле. Проверете и видимото съдържание на снимките.
4. Подгответе EN превод чрез бутона или ръчно. Прегледайте го. Отбележете проверката на местоположението и съдържанието, публикувайте.
5. Изберете автоматична или ръчна цена и следене на наличността. Ръчното съдържание не се презаписва от импорта. При конфликт с друг запис/синхронизация редакторът отказва да презапише новата версия.
6. В **Райони** редактирайте имената, текстовете и видимостта. В **Календар** добавете свободни часове. Едва тогава агентът може да предложи реални огледи.

Няма автоматично генериране на 50–100 „проверени“ имота. Това е редакционната цел на Никола и се запълва постепенно. Базата може да съдържа повече чернови, отколкото публикувани обяви.

## 6. Build, deploy и приемане

```bash
npm run build
npx wrangler deploy --dry-run
npx wrangler deploy
```

За GitHub/Cloudflare Builds: Node 24, build `npm run build`, deploy `npx wrangler deploy`. Миграцията на D1 се изпълнява преди първия deploy с `DB` binding. Запазете binding IDs в конфигурацията, не само в dashboard.

Преди launch проверете на staging:

- Публикуван имот се вижда на BG/EN на един и същ canonical slug; чернова, продаден и свален имот не се виждат.
- Цена се променя след sync; редакционното описание остава същото. Неуспешен импорт не скрива каталога.
- В текстов и гласов разговор въпрос за текущата обява използва нейния ID; нови критерии обновяват показаните карти.
- Неизвестен факт води до уточнение/Никола, а не до измислен отговор. „Близо до Априлци“ включва подходящ Кръвеник.
- Запазването на оглед изисква изрично потвърждение и само един клиент за един слот.
- Запитване „Предложете имот“ влиза в панела като продажба.
- Тестов разговор доставя подписан webhook, транскрипция и (ако е включено) възпроизводим запис.
- При телефонен режим направете реално тестово обаждане, проверете съобщението за запис и настройката на оператора.

Техническа документация: [ElevenLabs JavaScript SDK](https://elevenlabs.io/docs/eleven-agents/libraries/java-script), [post-call webhooks](https://elevenlabs.io/docs/eleven-agents/workflows/post-call-webhooks), [agent creation API](https://elevenlabs.io/docs/api-reference/agents/create).
